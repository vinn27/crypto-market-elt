How this dashboard works

CryptoELT is a fully autonomous crypto-market analytics pipeline. Every morning it fetches fresh data from CoinGecko, lands it raw in a Snowflake warehouse, rebuilds a tested star schema with dbt, and publishes this page — with no human pressing any buttons.

Why “indexed to 100”? Coins have wildly different price levels — $82,000 vs $2.50 on one chart flattens the small one. Rebasing every series to 100 at the window start compares shape on a single honest axis, instead of the misleading shortcut of drawing two y-axes on one chart.

02 Where the data comes from

The CoinGecko public API — free, no API key. Two endpoints:

EndpointGivesLands in
/coins/marketsTop-50 snapshot: prices, market cap, volume, 24h change, supplyRAW.COINS_MARKETS
/coins/{id}/market_chart90 days of daily price / cap / volume for the top 10 coinsRAW.COIN_MARKET_CHART

Raw rows are landed exactly as received — no renaming, no cleaning, timestamps kept as strings. Every load is stamped with loaded_at, and re-runs simply append: nothing is ever mutated or deleted in RAW.

MARTS

The star schema: one big fact of daily numbers plus two small dimensions that describe the coins and the calendar.

ELT, not ETL. The classic pattern cleans data before loading it (transform outside the database). This project loads first and transforms inside Snowflake with SQL under version control — because modern warehouses make in-warehouse SQL transforms fast, cheap, and re-runnable, and raw data is never lost to a buggy transform.

04 The star schema

One big table of numbers (the fact), surrounded by small tables of descriptions (the dimensions), connected by IDs — draw it and it looks like a star.

dim_coins

one row per coin
  • symbol, name, market-cap rank
  • supply figures
  • all-time high / low + dates

fact_market_snapshots

one row per coin per day
  • price
  • market cap
  • 24h volume
  • → joins to both dims by ID

dim_date

one row per day
  • day name, weekday number
  • month
  • grows itself as new days arrive

Why split? Same reason a school register uses roll numbers instead of full names on every line: no repetition, no drift. Descriptions live once in a dimension; the fact stays small and numeric. The weekday chart on the dashboard is this design paying rent — a plain date can't tell you it's a Saturday; dim_date can.

05 Data quality — 15 checks, every night

Every pipeline run ends with dbt tests. A test is a SELECT that hunts for bad rows — zero rows found means pass; anything else fails the run loudly.

CheckProtects against
not_null on every key columnrows that lost their identity in loading
unique on coin IDs and datessneaky duplicates in dimensions
relationships fact → dimsfacts pointing at coins/dates that don't exist
no duplicate fact rowsthe same coin-day loaded twice
prices are positivebroken source data (zero / negative prices)

The pipeline also defends itself at the edges: API rate-limits get retry-with-backoff (honouring Retry-After), and one tracked coin is newer than 90 days, so it simply arrives with fewer days — the schema absorbs it instead of breaking.

06 The pipeline behind this page

Nobody presses a button — every morning at 06:35 IST, GitHub Actions rents a small computer and runs the whole pipeline end to end: fetch, load, transform, test, export, publish. Fresh JSON is committed to the repository as a visible data trail, and the site is deployed straight to Netlify's CDN.

Visitors never touch Snowflake. The dashboard is a static page reading static JSON — no database connection, no credentials in the browser, no per-visit compute cost. The only machine that ever pays for queries is the nightly runner, and the warehouse itself sleeps (auto-suspend after 60 idle seconds) whenever it isn't being queried.

08 Reproduce it

Everything lives in vinn27/crypto-market-elt. With a free Snowflake trial account:

pip install -r requirements → fill .env from .env.example → python pipelines/setup_snowflake.py → python pipelines/extract_load.py → dbt build. The warehouse structure, tables, tests and this site all rebuild from the repo.
